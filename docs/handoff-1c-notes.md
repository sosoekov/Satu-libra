# Сводка для ТЗ на 1С:8.5: от найденного кандидата до старта стажировки (FT_17)

Сводка для автора ТЗ на разработку в 1С:8.5 по доработке прототипа «Личный кабинет руководителя». Источники: ТЗ `docs/tz-ft17-candidate-to-internship.md` и решения по фазам `docs/ft17-candidate-to-internship.md`. Соответствие элементов формы — `prototype/1c-mapping.md`.

Соответствие объектам 1С везде дано как **предложение**, а не как решение.

## 1. Сущности и поля

### 1.1. Стажер (найденный кандидат)

В прототипе — та же сущность, что стажер (`DATA.trainees`). Этапы расширены.

| Поле прототипа | Назначение | Есть в системе / новое |
|---|---|---|
| `id`, `fullName`, `position`, `departmentId` | ФИО, должность, подразделение | Есть |
| `requisitionId` | Заявка на подбор (только чтение) | **Новое** |
| `foundAt` | Дата и время «Исполнено» HR по задаче подбора | **Новое** |
| `expectedStartDate` | Ожидаемая дата выхода (необязательно) | **Новое** |
| `hrId` | HR-менеджер стажера = HR, завершивший подбор | Есть (FT_8); источник значения — новое |
| `stage` | Этап. Новые значения `pending_decision` (ожидает решения), `cancelled` (отменено). Статус ТЗ `awaiting_ap` — существующий этап `found` «Подготовка к выходу» | Расширено |
| `headId` | Руководитель стажировки — задается при старте | Есть |
| `mentorId` | Наставник — задается при старте | Есть |
| `startDate`, `endDate` | Дата старта (выхода) и окончания | Есть; задаются при старте |
| `durationMode` | Режим длительности: `1m`, `3m`, `6m`, `custom` | **Новое** |
| `checklistCreated` | Признак: стандартный чек-лист создан | **Новое** |
| `stageDates.found` | Дата перехода в «Подготовку к выходу» | Есть |
| `cancelReason`, `cancelledAt`, `cancelledBy` | Причина, дата и время, кто отменил | **Новое** |
| АП (`programs[].traineeId`) | Адаптационная программа, создается существующей логикой | Есть |

**Предложение.** Справочник «Сотрудники» (или «Стажеры») + регистр сведений «СтатусыСтажеров» (Стажер, Статус, Период, Автор). Поля старта — реквизиты стажера или документа «Старт стажировки».

**Причина отмены должна сохраняться в карточке физического лица**, чтобы HR видели ее позже. В прототипе она хранится в записи стажера (`cancelReason`), отдельного экрана нет.

### 1.2. Заявка на подбор

`DATA.vacancyRequests` — существует с FT_15. Поля: номер, дата, состояние, должность, подразделение, автор, требуемое количество, кандидатов в проработке, найдено, внеплановая, замена, срок закрытия, дата закрытия.

FT_17 меняет «Найдено» и состояние **только** при «Исполнено» HR (см. 2.1). Старт и отмена заявку не меняют.

**Предложение:** документ «ЗаявкаНаПодборПерсонала» модуля подбора.

### 1.3. Сотрудники и подразделения

- **Подразделения** — полная структура заказчика, 4 уровня: ЦАС → отдел → направление → группа. Есть с FT_8, расширено.
- **Сотрудники.** У пользователя появилось подразделение (`departmentId`) — **новое**. Добавлены сотрудники по списку заказчика.
- **Ответственный за подразделение** (`responsibleId`) — есть с FT_6. Для «Отдела корпоративных проектов» и «Отдела отчетности, НСИ и бизнес-процессов» он заменен по данным заказчика.

**Предложение:** «Сотрудники» с текущим подразделением из кадровых данных; руководитель подразделения — реквизит справочника «Подразделения».

### 1.4. Уведомления

| Источник | Получатель | Текст | Ссылка |
|---|---|---|---|
| «Подбор» | Автор заявки | «Кандидат на должность «…» принял предложение о работе: ФИО» | `candidateId` — на кандидата |
| «Адаптация» | Руководитель стажировки, наставник | «Вы назначены руководителем стажировки / наставником стажера ФИО: стажировка с ДД.ММ.ГГ по ДД.ММ.ГГ» | На стажера |

Есть с FT_10 (регистр уведомлений). Новое — тексты и ссылка на кандидата.

## 2. События и переходы статусов

```
(HR «Исполнено» по задаче подбора)
        │
        ▼
 pending_decision «Ожидает решения» ──«Отменить» + причина──► cancelled «Отменено» (нигде не отображается)
        │
        └──«Старт стажировки» + «Подтвердить»──► found «Подготовка к выходу» (= awaiting_ap «Ожидает АП»)
                                                    │
                                                    └──создание АП (сразу или позже)──► draft «Черновик АП» → … как раньше
```

| Событие | Кто | Что происходит | Функция прототипа |
|---|---|---|---|
| HR нажал «Исполнено» по задаче подбора | HR-менеджер | 1. Создается стажер на этапе `pending_decision` (должность и подразделение — из заявки), `foundAt` = сейчас.<br>2. У заявки «Найдено» +1, «Кандидатов в проработке» −1; когда найдено требуемое количество, заявка закрывается.<br>3. Автору заявки — уведомление «Подбор». | `registerFoundCandidate` |
| «Перейти» в уведомлении | Получатель | Вкладка «Адаптация персонала», карточка кандидата подсвечивается. После старта — карточка стажера, после отмены — сообщение | `goToCandidate` |
| «Прочитано» | Получатель | Только отметка прочитанного; на кандидата не влияет | — |
| «Отменить» → «Подтвердить отмену» | Автор заявки или заместитель руководителя ЦАС | `cancelled`, причина, дата и время, автор. Заявка не меняется, HR не уведомляется | `cancelCandidate` |
| «Старт стажировки» → «Подтвердить» | Автор заявки или заместитель руководителя ЦАС | 1. Сохраняются руководитель стажировки, наставник, даты и режим.<br>2. Этап `found` (дата этапа — сегодня).<br>3. Создается стандартный чек-лист, `checklistCreated`.<br>4. Руководителю стажировки и наставнику — уведомления «Адаптация» (кроме текущего пользователя).<br>5. Открывается «Стажировка оформлена». | `startInternship`, `createStandardChecklist`, `notifyAssigned` |
| «Создать АП» → способ | Тот же пользователь | Существующая форма создания АП выбранным способом (шаблон / копирование / с нуля); затем этап `draft` — как у любого стажера | `startApCreation` |
| «Позже» / крестик | Тот же пользователь | Стажер остается на `found`; АП создается позже со страницы «Адаптационная программа» тем же `startApCreation` | — |

## 3. Правила и проверки

1. **Видимость кандидата.** Все, кто видит подразделение по правилам FT_9 (заместитель руководителя ЦАС, HR-менеджеры — все; руководитель отдела — свой отдел), и автор заявки. Сотрудник КШ и стажер не видят.
2. **Решение** («Старт стажировки», «Отменить») принимает автор заявки или заместитель руководителя ЦАС. У остальных кнопки недоступны с подсказкой «Решение принимает автор заявки: ФИО».
3. **Счетчик вкладки «Адаптация персонала (N)»** = стажеры, требующие действия, + кандидаты, ожидающие решения.
4. **Причина отмены:** обязательна, не меньше 3 значащих символов (пробелы не считаются). Сохраняется без крайних пробелов.
5. **Списки «Руководитель стажировки» и «Наставник»:** сотрудники подразделения стажера со всеми вложенными подразделениями (группами) + руководители (ответственные) вышестоящих подразделений.
6. **Обязательность:** руководитель стажировки, наставник, дата старта, дата окончания. Руководитель стажировки и наставник — разные сотрудники; по умолчанию оба не заполнены.
7. **Дата старта:** по умолчанию — текущая дата; дата в прошлом недопустима.
8. **Дата окончания** — строго позже даты старта, иначе ошибка под полем и «Подтвердить» недоступна. Режимы:
   - 1, 3, 6 месяцев: окончание = старт + N календарных месяцев (если в итоговом месяце нет такого числа — последний день месяца) − 1 день. Примеры:
     - 15.10.2026 + 3 мес. → 14.01.2027;
     - 31.01.2027 + 1 мес. → 27.02.2027;
     - 31.08.2026 + 6 мес. → 27.02.2027;
     - 31.01.2028 + 1 мес. → 28.02.2028.
   - Смена даты старта пересчитывает окончание во всех режимах, кроме «Произвольная дата».
   - Ручное изменение даты окончания переключает режим в «Произвольная дата».
   - Количество дней не вводится и не считается.
9. **Стандартный чек-лист** — из шаблона чек-листа подготовки, не зависит от должности. Ответственные — по ролям (руководитель стажировки, наставник, HR-менеджер стажера). Сроки — от даты старта.
10. **Создание АП** — существующие три способа. Второй вход (форма «Стажировка оформлена») вызывает ту же процедуру с предвыбранным способом.

## 5. Только для прототипа (не переносить)

- «Демо: HR нашел кандидата» (`ДемоКнопкаHRНашелКандидата`) — имитация «Исполнено» HR; тестовые ФИО кандидатов по кругу.
- Подсветка карточки на 2,5 секунды после «Перейти». В 1С — активизация строки.
- Всплывающие сообщения — `ПоказатьОповещениеПользователя()`, если нужны.
- Демо-дата «сегодня» 25.07.26 и сброс демо перезагрузкой страницы (данные не сохраняются).
- Вид карточек вместо строк таблицы и «Старт стажировки» с контуром вместо заливки (в прототипе на экране одна основная кнопка).

## 6. Вопросы и допущения

### 6.1. Допущения ТЗ (раздел 11), реализованы как написано, помечены `// ASSUMPTION` в `prototype/app.js`

1. Кандидат появляется на вкладке в момент «Исполнено» HR и не зависит от «Прочитано».
2. Поля карточки: ФИО, должность, подразделение, заявка, дата уведомления, необязательная ожидаемая дата выхода.
3. Руководитель стажировки и наставник не совпадают.
4. Руководитель стажировки и наставник по умолчанию не заполнены.
5. Окончание = старт + N календарных месяцев − 1 день.
6. Дата окончания строго позже даты старта.
7. HR об отмене не уведомляется.
8. Назначенному, совпадающему с текущим пользователем, уведомление не создается.

### 6.2. Решения, принятые с заказчиком по ходу работы

1. Кандидаты — в отдельном блоке и фильтре, а не в таблице и дереве стажеров.
2. Решение принимают автор заявки и заместитель руководителя ЦАС.
3. Подразделение для списков — с вложенными группами + руководители выше.
4. Сотрудники и структура — по списку заказчика.
5. Отделы федеральных проектов и экспертизы — в ЦАС.
6. Уведомление о демо-кандидате получает автор заявки.

### 6.3. Открытые вопросы

1. **«Отдел по работе с субподрядчиками».** Его нет в структуре заказчика; оставлен ради тестовой заявки ЗП-000043. Удалить или перенести заявку?
2. **Кнопка «Старт стажировки».** Выделена контуром, а не синей заливкой: карточек может быть несколько, а основная кнопка на экране — одна. Подтвердить вид.
3. **Закрытие заявки.** В прототипе заявка закрывается, когда найдено требуемое количество; при количестве больше 1 она остается в работе. В ТЗ сказано «заявка в любом случае остается закрытой» — проверить для заявок на несколько человек.
4. **Квалификационный уровень и семейство должности** (FT_11) у кандидата не заполняются; при старте не запрашиваются. Нужно ли их задавать при старте?
5. **Тексты уведомления «Подбор»** для автора заявки — проверить формулировку с модулем подбора.
6. **ФИО в уведомлении о назначении** — полное, а не с инициалами, как в примере ТЗ.
