# Фаза 10. Блок аналитики, блокировка подготовки, вкладка «Закрытие стажировки»

> Дополнение к `tz-adaptation-prototype.md` и фазам 7–9. Где этот документ противоречит им, прав этот документ. Ограничения основного ТЗ (разделы 2, 3, 8) действуют.
>
> Работай по подфазам 10.1 → 10.5. После каждой — проверки из раздела 10 основного ТЗ и приёмка из раздела 7 этого документа, затем краткий отчёт и остановка.

## Цель

Интерфейс перегружен. В этой фазе:

1. Уведомления собираются в сворачиваемый блок «Аналитика по адаптационной программе» со счётчиком.
2. Действия переезжают туда, где идёт работа: в карточку и во вкладки. Блок аналитики — только обзор, без него можно работать.
3. Завершённая подготовка к выходу блокируется от изменений.
4. Появляется вкладка «Закрытие стажировки» со своим чек-листом. Она заменяет диалог «Начать закрытие стажировки».

Вкладки стажёра выстраиваются по жизненному циклу: **Подготовка к выходу → Адаптационная программа → Закрытие стажировки**. Отдельного степпера нет.

## 2. Подфаза 10.1. Карточка и размещение действий

Текущая раскладка на скриншоте ревью в целом верная, фиксируем её.

```
← Все стажёры                                                                        ⋮   ?
┌──────────────────────────────────────────────────────────────────────────────────────────┐
│ ОД  Орлова Дарья Павловна    Наставник: Новиков Павел Сергеевич    Даты стажировки            │
│     Руководитель проектов    Руководитель: Петрова Анна Евгеньевна 15.06.26 – 15.09.26  ███░ До закрытия: 28 дней   [Продлить срок] │
└──────────────────────────────────────────────────────────────────────────────────────────┘
▸ Аналитика по адаптационной программе (1)
Подготовка к выходу 7/7   Адаптационная программа   Закрытие стажировки 2/6
```

### 2.1. Где какое действие

| Действие | Где | Когда видно |
|---|---|---|
| ⋮ (История изменений АП, Открыть документ АП, —, Отменить стажировку), ? | Строка «← Все стажёры», справа | Всегда |
| Продлить срок | Карточка, справа | `active`, `closing` |
| Отозвать с согласования | Карточка, справа (на месте «Продлить срок») | `approval` |
| Создать АП | Пустое состояние вкладки АП (основное ТЗ 7.5.5) | Нет АП |
| **Отправить на согласование** | Командная панель вкладки АП, справа. **Основная кнопка** | `draft` или `changedAfterApproval` |
| Печать АП | Командная панель вкладки АП | АП существует |
| **Завершить стажировку** | Командная панель вкладки «Закрытие стажировки», справа. **Основная кнопка** | `closing` |

### 2.2. Карточка

- Вторая строка справа по этапу (заменяет фазу 9, 3.2):
  - `found`, `draft`, `approval` до выхода — «Выход через N дней»;
  - `active`, `closing` — полоса срока и «До закрытия: N дней»; при `lag` под полосой «Задачи отстают от графика» (`--c-warning`);
  - `closed` — «Стажировка закрыта ДД.ММ.ГГ» / «отменена ДД.ММ.ГГ».
- «До закрытия» — это дни до `endDate`, со склонением.

## 3. Подфаза 10.2. Блок «Аналитика по адаптационной программе»

### 3.1. Вид

Сворачиваемая группа без рамки и без фона. В 1С — обычная группа с `Поведение = Свертываемая`.

- **Заголовок:** стрелка ▸/▾, текст «Аналитика по адаптационной программе (N)», цвет `--c-primary`, 13px, обычное начертание.
- **Содержимое:** список уведомлений, каждое — строка 32px: цветная иконка 16px, текст `--c-text`, обычная кнопка. Отступ содержимого слева 20px (под текстом заголовка).
- **Все кнопки в блоке обычные**, основных нет. Основные действия живут во вкладках (2.1).
- Отступы: 16px от карточки, 16px до вкладок; в развёрнутом виде 8px между заголовком и списком.

### 3.2. Счётчик и видимость

- `N` = число «важных вопросов» — уведомлений из `getNotifications(trainee)`, у которых есть кнопка (все типы из 3.4). Считается без учёта текущей вкладки и фильтров, поэтому не меняется при переключении вкладок.
- Если `N = 0`, блок не показывается совсем.
- По умолчанию блок **свёрнут**.
- Состояние «свёрнут/развёрнут» общее для всех стажёров и сохраняется при переключении между ними до перезагрузки страницы.

### 3.3. Уведомление, ведущее в текущий вид

Строка остаётся (счётчик не должен расходиться со списком), но кнопка «Показать» / «Перейти…» скрывается, если:

- `target.tab` равен активной вкладке, **и**
- у `target` нет `filter` или он совпадает с текущим значением тумблера.

### 3.4. Список уведомлений (заменяет таблицу фазы 9, 2.1)

| id | severity | kind | Текст | Кнопка | target |
|---|---|---|---|---|---|
| `no_program` | warning | action | Для стажёра нужно создать адаптационную программу. Выход через N дней | Создать АП | — (открывает вкладку АП с пустым состоянием) |
| `prep_overdue` | danger | navigation | Просрочено пунктов подготовки к выходу: N | Показать | `{ tab: 'prep' }` |
| `draft_stale` | warning | action | АП не отправлена на согласование уже N дней | Отправить на согласование | — |
| `rejected` | danger | action | АП возвращена на доработку: «комментарий» | Отправить на согласование | — |
| `changed_after_approval` | warning | action | АП изменена после согласования. Отправьте её на повторное согласование | Отправить на согласование | — |
| `tasks_overdue` | danger | navigation | Просрочено задач: N | Показать | `{ tab: 'program', filter: 'overdue' }` |
| `lag` | warning | navigation | Задачи отстают от графика: выполнено X% при прошедших Y% срока | Показать невыполненные | `{ tab: 'program', filter: 'in_progress' }` |
| `close_soon` | info | navigation | До окончания стажировки N дн. Пора закрывать стажировку | Перейти к закрытию | `{ tab: 'closure' }` |
| `closure_overdue` | danger | navigation | Просрочено пунктов закрытия стажировки: N | Показать | `{ tab: 'closure' }` |
| `closure_ready` | info | action | Все обязательные пункты закрытия выполнены | Завершить стажировку | — |

Порядок — по фазе 9, 2.2 (danger → warning → info, внутри уровня action выше navigation).

`close_soon` показывается, пока этап `closing` и `closure_ready` ещё не наступил.

## 4. Подфаза 10.3. Блокировка вкладки «Подготовка к выходу»

### 4.1. Условие

Вкладка заблокирована, если одновременно:

- выполнены все пункты чек-листа подготовки, **и**
- стажёр получил задачи: этап `active`, `closing` или `closed`.

Если условие не выполнено (например, стажировка идёт, а пункт не закрыт), вкладка редактируемая, как раньше.

### 4.2. Вид заблокированной вкладки

- Первая строка вкладки: иконка замка 16px и серый текст «Подготовка завершена ДД.ММ.ГГ. Изменения недоступны.» Дата — самая поздняя дата выполнения пункта.
- Командная панель (Добавить пункт, Заполнить по шаблону) скрыта. Тумблер «Все | Мои» остаётся — он не меняет данных.
- Флажки выполнения недоступны, показывают состояние.
- В колонке «Действие» остаются только ссылки на существующие документы («Заявка 0911-00118», «Открыть Bitrix»). Ссылок создания («Создать заявку») нет.
- Название вкладки — «Подготовка к выходу 7/7» с картинкой-галочкой (фаза 8, раздел 4), текст `--c-text-secondary`.

В 1С — `ТолькоПросмотр` у таблицы и видимость командной панели.

## 5. Подфаза 10.4. Вкладка «Закрытие стажировки»

### 5.1. Когда появляется

- Вкладка видна на этапах `closing` и `closed`. Стоит третьей, после «Адаптационной программы».
- **Автоматический переход в `closing`.** При загрузке данных и после любой смены этапа или сроков: если этап `active` и до `endDate` ≤ `CLOSE_AVAILABLE_DAYS` дней, этап становится `closing`.
- **Генерация чек-листа.** При переходе в `closing` чек-лист закрытия создаётся из шаблона (5.2), если его ещё нет.
- **Продление.** Если продление срока увело `endDate` дальше порога, этап возвращается в `active`. Вкладка скрывается, чек-лист закрытия сохраняется.
- **Вкладка по умолчанию.** Когда вкладка появилась, она открывается по умолчанию вместо «Адаптационной программы».

### 5.2. Шаблон чек-листа закрытия

Новая сущность в `data.js`:

```js
closureChecklist // ТЧ ЧекЛистЗакрытия: id, traineeId, name, responsibleRole, responsibleId,
                 //   offsetDays (от endDate: отрицательное — до окончания, положительное — после),
                 //   optional (bool), done, doneBy, doneAt, linkedDocType (null | 'forus' | 'sit')
```

Пункт 1 из постановки («руководителю стажировки и стажёру») разбит на **две строки**: у каждой строки один ответственный и один флажок.

| № | Пункт | Ответственный (роль) | Смещение, дн. | Обяз. | Действие |
|---|---|---|---|---|---|
| 1а | Заполнить отчёт и матрицы в Forus Team | Руководитель стажировки | −7 | да | `forus` |
| 1б | Заполнить отчёт и матрицы в Forus Team | Стажёр | −7 | да | `forus` |
| 2 | Провести мероприятие по закрытию стажировки | HR-менеджер | −3 | да | — |
| 3 | Оставить заявку о закрытии стажировки в СИТ | HR-менеджер | 0 | да | `sit` |
| 4 | Оставить заявки на открытие доступа к дополнительным материалам | Руководитель стажировки | 0 | **нет** | — |
| 5 | Подготовить список сотрудников, закрывших стажировку, и отправить его в КШ | HR-менеджер | +3 | да | — |
| 6 | Подготовить документы для оформления ДМС | КШ | +5 | да | — |

Смещения — предложение для прототипа, см. открытые вопросы.

Роль «Стажёр» — сам стажёр, в «Ответственном» его ФИО. В `users` добавить сотрудника с ролью «КШ».

### 5.3. Вид вкладки

По образцу вкладки подготовки (фаза 9, раздел 6).

**Командная панель:**

```
[+ Добавить пункт]                                    [Все | Мои]        [Завершить стажировку]
```

«Завершить стажировку» — основная кнопка. Недоступна, пока есть невыполненные обязательные пункты; рядом серым «Осталось обязательных пунктов: N».

**Колонки:** ☐ | Пункт | Ответственный | Срок | Действие.

- **Пункт** — наименование. У необязательного второй строкой серым «необязательно».
- **Ответственный, флажок** — как в фазе 9, 6.3.
- **Срок** — дата `endDate + offsetDays`, вторая строка:

| Состояние | Текст | Цвет |
|---|---|---|
| Не выполнено, срок до окончания | за N дн. до окончания | `--c-text-secondary` |
| Не выполнено, срок в день окончания | в день окончания | `--c-text-secondary` |
| Не выполнено, срок после окончания | через N дн. после окончания | `--c-text-secondary` |
| Не выполнено, срок прошёл | просрочено на N дн. | `--c-danger`, дата тоже |
| Выполнено | выполнено ДД.ММ | `--c-text-secondary` |

- **Действие:**
  - `forus` — «Открыть Forus Team» (оповещение-заглушка);
  - `sit` — «Открыть СИТ» (оповещение-заглушка);
  - флажок в обоих случаях ставится вручную.

Сортировка всегда по сроку.

**Название вкладки:** «Закрытие стажировки X/Y», где Y — число **обязательных** пунктов, X — выполненных обязательных. Картинка страницы:

- все обязательные выполнены — галочка;
- есть просроченные — «!»;
- иначе нет картинки.

### 5.4. Завершение

«Завершить стажировку» открывает диалог (бывший «Начать закрытие стажировки»):

- сводка: выполнено X из Y задач АП, просрочено N;
- результат: «Стажировка пройдена» / «Не пройдена» (обяз.);
- комментарий;
- кнопка «Завершить стажировку».

Результат:

- этап `closed`;
- запись в историю;
- оповещение «Стажировка завершена»;
- все три вкладки только для просмотра;
- на вкладке закрытия первая строка — замок и «Стажировка завершена ДД.ММ.ГГ. Изменения недоступны.»

### 5.5. Тестовые данные

- **Попова** (`closing`): чек-лист закрытия сгенерирован, выполнены 1а, 1б и 2. Если по `TODAY` у какого-то невыполненного пункта срок прошёл — он просрочен, это ожидаемо.
- У остальных стажёров чек-листа закрытия нет, пока они не перейдут в `closing`.

## 7. Приёмка

Окно 1600×900, свежая загрузка, если не сказано иное.

**Блок аналитики (10.1, 10.2)**

1. **Орлова.** Блок свёрнут, в заголовке «(N)», N равно числу уведомлений в развёрнутом списке. Ни одной кнопки внутри блока в свёрнутом виде не видно.
2. Развернуть блок, переключиться на Лебедева → блок развёрнут. Перезагрузить страницу → свёрнут.
3. У Орловой на вкладке АП развернуть блок, нажать «Показать» у просроченных задач → тумблер «Просрочено». Строка уведомления осталась, кнопка «Показать» у неё исчезла, число в заголовке не изменилось.
4. **Смирнов** (нет уведомлений) — блока нет. Вкладки стоят сразу после карточки с отступом 16px ±2.
5. На любом экране, в том числе с развёрнутым блоком, основных кнопок не больше одной. Внутри блока основных кнопок нет.
6. **Сидоров** (`draft`). Кнопка «Отправить на согласование» (основная) есть в командной панели вкладки АП при свёрнутом блоке.

**Блокировка подготовки (10.3)**

7. **Орлова.** Вкладка «Подготовка к выходу 7/7»: строка с замком и датой, нет «Добавить пункт» и «Заполнить по шаблону», флажки недоступны, нет ссылок «Создать заявку», ссылки на существующие заявки есть. Тумблер «Все | Мои» работает.
8. **Иванов** (`found`) — вкладка редактируемая.
9. Через демо-переключатель перевести Иванова (подготовка 2/7) в «Стажировку» → вкладка подготовки **не** заблокирована, в блоке аналитики есть «Просрочено пунктов подготовки».

**Вкладка закрытия (10.4)**

10. **Лебедев** (до окончания > 14 дней) — вкладки «Закрытие стажировки» нет.
11. **Попова.** Три вкладки в порядке Подготовка → АП → Закрытие; по умолчанию открыта «Закрытие стажировки»; название «Закрытие стажировки 3/6»; в таблице 7 строк, у пункта 4 подпись «необязательно»; у 1б в «Ответственном» — «Стажёр», «Попова Елизавета Андреевна».

## 8. Открытые вопросы

В прототипе принято временное решение (в скобках); сверх него не расширять.

1. Название блока. Внутри не аналитика, а вопросы, требующие действия. Может, назвать «Требует внимания», как фильтр в левой панели? *(Оставлено «Аналитика по адаптационной программе».)*

3. Сроки пунктов закрытия относительно даты окончания. *(Предложены в 5.2.)*

## 9. Решения, принятые при реализации

Согласованы с заказчиком до начала работ.

1. **Пункт приёмки 16.** Порог — **≤ 530px** при свёрнутом блоке аналитики. Раскладка делается строго по ТЗ с отступами 16/8px фазы 9. Главный критерий плотности — не меньше 8 видимых строк задач.

Приняты при реализации, вынесены на проверку заказчика в отчётах по подфазам.

2. **Строки справа в карточке (10.1).** Первая строка — «Даты стажировки» и даты. Вторая — по этапу, как в 2.2: полоса срока 64px и «До закрытия: N дней» / «Выход через N дней» / «Стажировка закрыта (отменена) ДД.ММ.ГГ». Третья — «Задачи отстают от графика» при отставании. Если поставить даты, полосу, «До закрытия» и кнопку в одну строку, как в эскизе раздела 2, карточка при 1600 выходит за рамку на 12–47px.
3. **Карточка при ширине окна до 1500px (10.1).** Колонка дат и кнопка «Продлить срок» / «Отозвать с согласования» переносятся второй строкой внутри карточки, ФИО наставника и руководителя не обрезаются. Это заменяет решение 3 фазы 9, где ФИО обрезались многоточием. Высота карточки при 1366 — 118px, при отставании — 138px.
4. **Главное действие этапа в блоке уведомлений** (решение 2 фазы 9) убрано: «Отправить на согласование» теперь в командной панели вкладки АП (2.1).
