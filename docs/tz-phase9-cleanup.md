## 2. Подфаза 9.1. Логика уведомлений

### 2.1. Поля уведомления

Функция `getNotifications(trainee)` возвращает для каждого уведомления:

```js
{
  id,          // стабильный код: 'no_program', 'prep_overdue', 'draft_stale', 'rejected',
               // 'changed_after_approval', 'tasks_overdue', 'lag', 'close_soon'
  severity,    // 'danger' | 'warning' | 'info'
  kind,        // 'action' — кнопка меняет данные; 'navigation' — кнопка только переключает вид
  text,        // полный текст (основное ТЗ 7.1)
  shortText,   // короткий текст (фаза 7, 3.2)
  buttonText,  // «Создать АП», «Отправить на согласование», «Начать закрытие стажировки», «Показать»
  target       // только для navigation: { tab: 'prep' } или { tab: 'program', filter: 'overdue' | 'in_progress' }
}
```

| id | severity | kind | target |
|---|---|---|---|
| `no_program` | warning | action | — |
| `prep_overdue` | danger | navigation | `{ tab: 'prep' }` |
| `draft_stale` | warning | action | — |
| `rejected` | danger | action | — |
| `changed_after_approval` | warning | action | — |
| `tasks_overdue` | danger | navigation | `{ tab: 'program', filter: 'overdue' }` |
| `lag` | warning | navigation | `{ tab: 'program', filter: 'in_progress' }` |
| `close_soon` | info | action | — |

### 2.2. Порядок

1. По важности: danger → warning → info.
2. Внутри одного уровня важности `action` идёт выше `navigation`.
3. Внутри одного уровня и вида — в порядке таблицы 2.1.

### 2.3. Скрытие уведомления, которое ведёт в текущий вид

В блоке процесса (раздел 3) навигационное уведомление не показывается, если пользователь уже там, куда оно ведёт:

- `target.tab` равен активной вкладке, **и**
- у `target` нет `filter` или `filter` совпадает с текущим значением тумблера статусов.

Правило касается только блока процесса. Дерево, счётчик «Требуют внимания», счётчик на вкладке верхнего уровня и сводная таблица считают уведомления без учёта текущего вида.

### 2.4. Какие уведомления куда попадают

| Место | Какие уведомления |
|---|---|
| Блок процесса | Все, кроме скрытых по 2.3 |
| Иконка в дереве | Только danger и warning; иконка по самому важному |
| Колонка «Требует действия» сводной таблицы | Все, как в фазе 7 |
| «Требуют внимания» и счётчик на вкладке | Стажёры с хотя бы одним danger или warning |

## 3. Подфаза 9.2. Карточка стажёра и блок процесса (вариант Б)

### 3.1. Раскладка

```
← Все стажёры

┌───────────────────────────────────────────────────────────────────────────────────────────┐
│ ИП  Иванов Петр Сергеевич     Наставник: Козлов Дмитрий Андреевич       29.07.26 – 28.10.26 │
│     Аналитик                  Руководитель: Петрова Анна Евгеньевна     Выход через 4 дня   │
└───────────────────────────────────────────────────────────────────────────────────────────┘
                                                                              ↕ 16px
 ✓ Подготовка к выходу ── ✓ Черновик АП ── ● Согласование ── ○ Стажировка ── ○ Закрытие ── ○ Закрыта
                                           с 25.07.26
                                                                              ↕ 8px
 ⚠  Для стажёра нужно создать… [Создать АП]                  Продлить срок   Печать АП   ⋮   ?
 !  Просрочено пунктов подготовки: 1  [Показать]
                                                                              ↕ 16px
 Подготовка к выходу 2/7   Адаптационная программа
```

### 3.2. Карточка стажёра — только данные о человеке и стажировке

- **Единственный блок с рамкой** в центральной области. Внутренние отступы 12px сверху и снизу, 16px слева и справа. Высота — не больше 72px.
- **Слева:** аватар 40px с инициалами, ФИО (18px, полужирный), под ним должность.
- **В середине:** «Наставник: ФИО» и «Руководитель: ФИО» (подпись серым, ФИО — гиперссылка).
- **Справа**, прижато к правому краю, две строки:
  - первая — даты «ДД.ММ.ГГ – ДД.ММ.ГГ»;
  - вторая — зависит от этапа:

| Этап | Вторая строка |
|---|---|
| `found`, `draft`, `approval` до даты выхода | «Выход через N дней», обычное начертание. Если N ≤ 3 — цвет `--c-warning` |
| `active`, `closing` | Две компактные полосы в одну строку: «Срок ███░░ 41/93», «Задачи ███░░ 65%». При отклонении — после процента текстом «, отстаёт от графика» (`--c-warning`) или «, опережает график» (`--c-text-secondary`) |
| `closed` | «Стажировка закрыта ДД.ММ.ГГ» или «Стажировка отменена ДД.ММ.ГГ» |

  Полосы в одной строке: каждая 64px, подпись слева, значение справа. Если при 1366px не помещаются — перенести «Задачи» третьей строкой, но высота карточки не должна превысить 88px.

### 3.3. Блок процесса

Отдельная вертикальная группа **без рамки и без фона**, отступ от карточки 16px. Две части.

**Степпер** — внешний вид по 8.1, подписи под шагами по фазе 8, раздел 2.1.

- Пройденный шаг: зелёная галочка, текст `--c-text` обычного начертания. **Зелёного текста больше нет.**
- Текущий шаг: кружок с номером, залитый `--c-primary`; текст `--c-primary`, полужирный.
- Будущий шаг: кружок с номером, контур `--c-border`; текст `--c-text-secondary`.
- Соединительные линии — `--c-border`, одного цвета.

**Уведомления и действия** — отступ от степпера 8px.

- **Строки уведомлений.** Показываются первые **два** уведомления из списка (после 2.2 и 2.3), каждое — отдельной строкой 32px. Строка — горизонтальная группа: цветная иконка 16px, текст `--c-text` обычного начертания, кнопка. **Цветного фона у строк нет.**
- **Основная кнопка.** Основной становится кнопка первого `action`-уведомления среди видимых строк. Остальные кнопки — обычные. Если `action` среди видимых нет — основной кнопки нет.
- **«Ещё N».** Если уведомлений больше двух, в конце второй строки — гиперссылка «ещё N». Она раскрывает остальные строки тем же видом, ссылка меняется на «Скрыть».
- **Второстепенные действия** (состав — фаза 8, 3.2) всегда стоят справа **на первой строке** блока. Если уведомлений нет, первая строка содержит только их. Горизонтальная позиция кнопок одинакова во всех состояниях.

## 4. Подфаза 9.3. Визуальная чистка

### 4.1. Вертикальный ритм

Между крупными блоками центральной области — 16px (`--sp-4`), внутри блока — 8px (`--sp-2`). Крупные блоки сверху вниз:

1. «← Все стажёры»;
2. карточка стажёра;
3. блок процесса;
4. вкладки;
5. содержимое вкладки (строка умолчаний / командная панель → таблица).

Других внешних отступов у этих блоков быть не должно — проверить, что отступы не складываются (margin + padding соседних блоков).

### 4.2. Рамки и таблицы

- Рамка есть только у карточки стажёра и у диалогов.
- Все таблицы (сводная, задачи АП, чек-лист, таблицы в диалогах) без внешней рамки. Заголовок — текст `--c-text-secondary` 12px без фона, под заголовком линия `--c-border`. Между строками — горизонтальные линии `--c-border`, вертикальных линий нет. В 1С — свойства `ГоризонтальныеЛинии`, `ВертикальныеЛинии` таблицы.
- Строки группировки в таблице задач — фон `--c-bg-panel`, это единственная заливка внутри таблиц.

### 4.3. Начертание

Полужирным остаются только:

- ФИО в карточке;
- подразделения в дереве;
- строки групп в таблице задач;
- заголовки диалогов;
- активная строка фильтра в левой панели;
- текущий шаг степпера.

Всё остальное — обычным начертанием, включая «Выход через N дней», числа в сводках и названия внутренних вкладок.

### 4.4. Вкладки стажёра

- Размер 13px, обычное начертание.
- Неактивная — `--c-text-secondary`, активная — `--c-text` и подчёркивание 2px `--c-tab-active`.
- Верхние вкладки кабинета не меняются и остаются визуально старше внутренних.
- Картинка страницы («!» или галочка) — по фазе 8, раздел 4.

### 4.5. Тумблеры

Относится к «Все | Мои» и к тумблеру статусов.

- Выбранный вариант: фон `--c-bg-selected`, текст `--c-primary`. Не выбранный: фон `--c-bg`, текст `--c-text`. Общая рамка `--c-border`.
- Сплошной заливки `--c-primary` у тумблеров быть не должно — она читается как основная кнопка.
- `data-1c-risk="check"`: в `1c-mapping.md` отметить, что вид тумблера рисует платформа, и сверить с платформенным видом 1С 8.5.

## 8. Подфаза 9.7. Технические исправления и соответствие 1С

### 8.1. Заголовок окна

- Демо-переключатель не должен выталкивать кнопки ⟳ ⋮ ✕. Кнопки окна прижаты к правому краю и не сжимаются. Переключатель стоит слева от них, максимальная ширина 240px, текст обрезается многоточием.
- Горизонтальной прокрутки страницы нет при ширине 1366, 1600 и 1920.

### 8.2. Согласованность демо-переключателя

При переводе стажёра на этап дальше `found`:

- если АП нет — создать её по шаблону, подходящему должности (иначе «Базовый»), со сроками от `startDate`;
- отметить пункт чек-листа «Создать АП» выполненным;
- записать в историю «Создана при смене этапа (демо)».

При возврате на `found` АП не удалять.

### 8.3. `1c-mapping.md`

- Обновить дерево групп: карточка стажёра без степпера; новая группа «ГруппаПроцесс» со степпером и строками уведомлений.
- Удалить из описания программное изменение цвета фона плашек: фона больше нет.
- Добавить: колонки дерева «Статус» и «Количество»; колонки чек-листа по 6.3; риск вида тумблера (4.5).
