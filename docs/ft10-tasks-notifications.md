# FT_10. Вкладка «Задачи и уведомления»

Требования заказчика (макет вкладки) и ответы на уточняющие вопросы. Всё, что здесь не упомянуто, работает как в FT_9.

## 1. Требования

1. Пользователь видит в списке только свои задачи.
2. По задаче сразу понятно, из какого блока она пришла — «Подбор персонала» или «Адаптация персонала», и что с ней делать — согласовать, ознакомиться или выполнить.
3. С уведомлениями так же: сразу понятно, откуда пришло уведомление и что с ним делать.
4. Шестерёнка рядом с «По важности» позволяет переименовать уровень важности. Настройки важности у каждого пользователя свои.

Макет:

- **Левая панель:** «Мои задачи N»; фильтры «Все задачи», «Просроченные», «Требуют внимания», «Сегодня»; флажки «По источнику» и «По типу задачи»; «По важности» — шестерёнка и флажки уровней с числом задач.
- **Центр:**
  - страницы «Задачи» | «Уведомления N»;
  - команды: «Перенаправить задачу», «Установить важность ▾», ⟳, поиск «Поиск по задачам…»;
  - сворачиваемые группы «Просроченные (N)», «Требуют внимания (N)»;
  - колонки: флажок | Задача (жирный глагол и предмет) | Источник | Тип задачи | Срок (дата и «Просрочено на N дн.» / «Осталось N дня») | Автор | Подразделение автора | Действие (кнопка «Согласовать ▾»).

## 2. Ответы на вопросы

| Вопрос | Ответ |
|---|---|
| Типы задач и команды | «Согласовать»: Согласовано / Не согласовано. «Выполнить»: Взять в работу / Выполнить. «Ознакомиться»: только «Ознакомиться». Новый тип «Проверить»: Проверено / Вернуть на доработку |
| Задачи адаптации и подбора | Задачи адаптации берутся из данных адаптации и связаны с ними — действие меняет данные. Задачи подбора — тестовые данные |
| Чьи задачи | У каждого демо-пользователя свои задачи, уведомления и настройки важности |
| Что происходит после действия | Задача уходит из списка. «Взять в работу» оставляет её с отметкой «В работе» |
| Какие события адаптации становятся задачами | Текущий шаг маршрута согласования АП → «Согласовать». Пункты чек-листов подготовки и закрытия, где пользователь ответственный → «Выполнить». Задача АП, которую стажёр отметил «Выполнено», → «Проверить» у проверяющего |
| Проверка задачи стажёра | «Вернуть на доработку» возвращает задачу стажёру в работу. «Проверено» завершает задачу |
| Статус задачи АП при проверке | Новый статус «На проверке». «Выполнено» стажёра у задачи с проверяющим → «На проверке», без проверяющего → «Выполнена». «Проверено» → «Выполнена», «Вернуть на доработку» → «В работе» |
| События «стажёр вышел», «АП согласована» | Уведомления, а не задачи |
| Группы и фильтр «Сегодня» | «Просроченные», «Требуют внимания» (срок сегодня или в ближайшие 3 дня), «Остальные». «Сегодня» — срок сегодня |
| Важность | До 6 уровней: «+» добавляет, корзина удаляет. Цвет флажка — автоматически. Шестерёнка — переименование. По умолчанию 3 флажка: красный «Важно», жёлтый «Средняя важность», синий «Прочие» |
| Автор | Полное ФИО, только существующие пользователи |
| Уведомления | Замечания аналитики адаптации по стажёру одной строкой (пример: «стажёр Петров выходит через 2 дня, не завершены подготовительные задачи, не создана АП, не согласована АП»), события адаптации, тестовые уведомления подбора. Действия «Перейти» и «Прочитано» |
| Кнопка с меню ▾ | Основная кнопка выполняет главную команду; в меню ▾: «Согласовано / Не согласовано», «Взять в работу / Выполнить», «Проверено / Вернуть на доработку». «Не согласовано» и «Вернуть на доработку» требуют комментарий |
| «Перенаправить» | Меняет исполнителя в данных: ответственного пункта чек-листа, согласующего текущего шага, проверяющего задачи АП, исполнителя задачи подбора |
| Двойной клик по строке | Адаптация — стажёр на вкладке «Адаптация персонала» (лист согласования / чек-лист / карточка задачи АП). Подбор — оповещение «Откроется документ …» |
| Стажёр и сотрудник КШ | Видят свои задачи: стажёр — задачи своей АП («Выполнить») и свои пункты закрытия, Баева — пункт закрытия «ДМС». Задач подбора у них нет |

## 3. Решения, принятые при реализации

### 3.1. Задачи

1. **Задачи адаптации** вычисляются из данных при каждом выводе, отдельно не хранятся:

   | Задача | Когда появляется | Срок | Автор |
   |---|---|---|---|
   | «Согласовать» | Пользователь — согласующий текущего шага маршрута | Срок шага, как в листе согласования | Кто отправил АП на согласование (из истории), иначе руководитель стажировки |
   | «Выполнить» по пункту чек-листа | Пользователь — ответственный за невыполненный пункт | Срок пункта | HR-менеджер стажёра; у пунктов самого HR-менеджера — руководитель стажировки |
   | «Проверить» | Задача АП «На проверке», пользователь — проверяющий | Срок задачи | Стажёр |
   | «Выполнить» у стажёра | Невыполненные задачи своей АП | Срок задачи | Руководитель стажировки |

   Уточнения:

   - Стажёр получает задачи своей АП только после согласования — на этапах «Стажировка» и «Закрытие».
   - Пункт «Создать АП» задачей не становится — он отмечается автоматически.
   - У закрытых стажировок задач нет.
2. **Подразделение автора** — подразделение, за которое автор отвечает; у стажёра — его подразделение. У HR-менеджеров и сотрудника КШ подразделения в справочнике нет — в колонке «—».
3. **Строка задачи:**
   - «Задача» — жирный глагол типа задачи и предмет. Второй строкой серым — откуда задача: например, «Подготовка к выходу · стажёр ФИО» или шаг маршрута.
   - Цвета типов: «Согласовать» — красный, «Выполнить» — зелёный, «Ознакомиться» — синий, «Проверить» — жёлтый.
   - Цвета источников: «Подбор» — фиолетовый, «Адаптация» — бирюзовый.
   - Флажок важности — перед текстом задачи; «В работе» — бейдж после текста.
4. **Срок:** дата; второй строкой — «Просрочено на N дн.» (красным), «Сегодня» или «Остался 1 день» / «Осталось N дней». Внутри групп задачи идут по сроку.
5. **Счётчики левой панели** считаются по всем задачам пользователя, без учёта отборов. Отборы складываются: фильтр по сроку, флажки источника и типа, уровень важности, поиск. Поиск ищет по задаче, стажёру, автору и подразделению.
6. **Действия:**
   - Кнопки в строке — обычные, не основные (на экране не больше одной основной кнопки).
   - У «Ознакомиться» меню ▾ нет.
   - В меню «Выполнить» пункт «Взять в работу» недоступен, если задача уже в работе.
7. **Как действия меняют данные:**
   - «Согласовано» / «Не согласовано» — результат текущего шага маршрута, как демо-кнопки листа согласования. Последний шаг переводит АП в «Стажировку». «Не согласовано» переводит АП в «Черновик АП», комментарий становится замечанием «возвращена на доработку».
   - «Выполнить» по пункту чек-листа — отметка выполнения пунктом текущего пользователя.
   - «Проверено» / «Вернуть на доработку» — статус задачи АП, запись в историю АП и уведомление стажёру (при возврате — с комментарием).
   - «Взять в работу» по пункту чек-листа — отметка «В работе» (только в списке задач, в чек-листе её нет).
8. **«Перенаправить задачу»** — для выбранных флажками задач: новый исполнитель (кроме себя) и необязательный комментарий. В историю АП записывается «… перенаправлено: кто → кому». Задачи своей АП стажёр не перенаправляет — кнопка недоступна, в форме пояснение.
9. **Двойной клик:**
   - Сотрудник КШ и стажёр (для пунктов чек-листов) раздел адаптации не видят — для них оповещение «Откроется … стажёра ФИО».
   - Задача «Проверить» и задача стажёра открывают карточку задачи АП.

### 3.2. Важность

10. **Важность** — личная настройка:
    - Хранится у пользователя: уровни и отметки задач.
    - Цвет флажка — по месту уровня в списке: красный, жёлтый, синий, зелёный, фиолетовый, серый. После удаления уровня цвета следующих сдвигаются.
    - Удаление уровня снимает его отметки у задач. Последний уровень удалить нельзя. Пустое название — ошибка под полем.
    - Для демонстрации у Стрыгина, Кладовой, Сизовой и Судомойкиной несколько задач уже отмечены.
11. **Отбор «По важности»** — клик по уровню, повторный клик снимает отбор. «Установить важность ▾» — уровни пользователя и «Снять важность», для выбранных задач.

### 3.3. Уведомления

12. **Уведомления:**

    - **Аналитика адаптации.** По каждому видимому стажёру — одно уведомление: все замечания блока аналитики одной строкой, важность по самому критичному.
      - Если выход через 7 дней или раньше (этапы «Подготовка», «Черновик АП», «Согласование»), в начале — «выходит через N дней», дальше — что не готово: «не завершены пункты подготовки к выходу: X из Y», «адаптационная программа не согласована».
      - Стажёр видит только просрочку своих задач («У вас N просроченных задач…»), сотрудник КШ — ничего.
    - **События адаптации за последние 7 дней**, кроме своих действий: АП отправлена на согласование, согласована, возвращена на доработку, начато закрытие, стажировка завершена или отменена, выход на стажировку.
    - **Адресные события** — результат проверки задачи стажёру.
    - **Уведомления подбора** — тестовые.

    Сортировка — по дате, новые сверху.
13. **«Прочитано»** убирает уведомление из списка. Уведомление по аналитике появится снова, если изменился набор замечаний.
14. **«Перейти»:**
    - Аналитика и события — стажёр на вкладке «Адаптация персонала».
    - Результат проверки — карточка задачи.
    - Подбор — оповещение.
15. **Левая панель на странице «Уведомления»:** «Мои уведомления N», фильтры «Все уведомления», «Критичные», «Требуют внимания», «Информация» и флажки «По источнику».

### 3.4. Экран и 1С

16. **Ширина экрана:**
    - Левая панель вкладки — 260px.
    - На ширине 1366 все колонки видны без горизонтальной прокрутки: длинные тексты — до двух строк с многоточием, полный текст в подсказке.
17. **1С:** кнопки в строках таблиц (`ТаблицаМоиЗадачиГруппаДействие`, `ТаблицаУведомленияГруппаДействие`) помечены риском high — варианты реализации в `prototype/1c-mapping.md`.
