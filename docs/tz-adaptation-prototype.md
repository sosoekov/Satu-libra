## 1. Контекст

Личный кабинет руководителя — форма в 1С 8.5 (управляемые формы). Вкладка «Адаптация персонала» позволяет руководителю подразделения:

1. Видеть статусы стажёров в своём и подчинённых подразделениях.
2. Открыть конкретного стажёра и смотреть прогресс по адаптационной программе (АП). Задачи АП делятся на корпоративный блок (общефирменные) и специальный блок (по должности).
3. Продлить, отменить или начать закрытие стажировки.
4. До выхода стажёра видеть чек-лист того, что руководителю и другим ответственным нужно подготовить.
5. Распечатать АП в формате .docx.
6. Получать уведомления по АП: сотрудник найден, нужно создать АП, АП не отправлена на согласование, АП согласована, скоро закрытие стажировки.
7. Отправлять АП на согласование.
8. Корректировать АП «вживую»: добавлять, удалять, редактировать задачи.
9. Создавать АП вручную или из шаблона.
10. Назначать проверяющих и наблюдателей по задачам АП.

Прототип нужен, чтобы проверить UX переработанного экрана до реализации в 1С. **Всё, что появится в прототипе, должно быть реализуемо штатными элементами управляемой формы 1С 8.5.** Это главное ограничение, важнее визуальной красоты.

## 2. Технические рамки

**Стек:** HTML + CSS. JavaScript — только для переключения состояний и работы с тестовыми данными (см. 2.2).

### 2.1. Структура файлов

```
prototype/
  index.html      — разметка
  styles.css      — все стили, токены в :root
  data.js         — тестовые данные (глобальная переменная window.DATA)
  app.js          — логика: рендер, фильтры, переключение состояний
  1c-mapping.md   — таблица соответствия элементов прототипа элементам формы 1С (генерируется в фазе 6)
```

### 2.2. Для чего JS разрешён

- выбор стажёра, переключение вкладок и режимов;
- фильтрация и поиск в дереве и таблицах;
- открытие/закрытие диалогов, подменю, контекстных меню;
- изменение тестовых данных в памяти (создание АП, смена этапа, отметка пунктов чек-листа, редактирование задач).

### 2.3. Не делать

- Никаких фреймворков, библиотек, сборщиков, npm, CDN, веб-шрифтов, внешних картинок. Проект должен открываться двойным кликом по `index.html` (протокол `file://`).
- Никаких `type="module"` и `import` — они не работают на `file://`. Только обычные `<script src="...">`.
- Не использовать localStorage/sessionStorage. Состояние сбрасывается при перезагрузке — это нормально.
- Не делать адаптив под мобильные. Целевое разрешение 1600×900, минимальное 1366×768 — для всего окна вместе с оболочкой клиента (2.4).
- Не использовать абсолютное позиционирование для раскладки, наложение элементов друг на друга, CSS Grid для раскладки формы (см. 3.1).
- Не использовать drag-and-drop. Порядок меняется кнопками ↑ ↓.
- Не делать функциональность, доступную только по наведению мыши. Подсказки через `title` — только для второстепенной информации.
- Не делать анимаций, кроме мгновенного показа/скрытия. Переходы допустимы только у hover-состояния кнопок (≤120 мс).
- Не рисовать кольцевые и прочие диаграммы через canvas/SVG-графики. Прогресс — только полосы (см. 7.5.1).
- Не генерировать реальный .docx. Печать — заглушка (см. 7.4).
- Не реализовывать вкладки «Задачи и уведомления» и «Подбор персонала» — только заглушка «Раздел не входит в прототип».
- Не добавлять функции, которых нет в этом ТЗ. Если кажется, что чего-то не хватает, — запиши в раздел «Вопросы» отчёта о фазе, но не реализуй.

Форма показывается внутри статичной имитации клиентского окна 1С 8.5, чтобы прототип читался как интерфейс 1С. Образец — скриншот пустого «Личного кабинета руководителя» в клиенте 8.5.

Состав оболочки:

- **Верхняя полоса:** логотип 1С и вкладка «Начало» (иконка домика, жёлтая метка слева, белый фон — активная вкладка).
- **Левая колонка:** иконки разделов (сверху) и кнопка панели разделов (внизу).
- **Правая колонка:** иконки поиска, оповещений, истории, избранного, разделитель, иконка функций текущего раздела; внизу — иконка пользователя.

- Оболочка **некликабельна**: без обработчиков, без курсора-указателя, без hover-состояний, не получает фокус. Размечается `<div>`/`<span>`, а не `<button>`.
- Всё, что относится к оболочке, включая заголовок формы и кнопки ⟳ ⋮, помечается `data-1c="НЕ_ПЕРЕНОСИТЬ"`: это рисует платформа.

## 3. Правила переноса в 1С

### 3.1. Раскладка = группы формы

Форма 1С строится из вложенных групп (вертикальных и горизонтальных). Прототип должен повторять эту модель:

- каждый контейнер — это `display: flex` с `flex-direction: row` (горизонтальная группа) или `column` (вертикальная группа);
- вложенность контейнеров отражает будущую вложенность групп формы;
- ширины задаются через `flex-basis` / фиксированные значения, а не через процентные сетки;
- не более 6 уровней вложенности групп.

### 3.2. Атрибуты соответствия

Каждый значимый элемент разметки помечается двумя атрибутами:

- `data-1c` — тип элемента формы 1С;
- `data-1c-name` — имя элемента в стиле 1С (ВерблюжийРегистр по-русски): `ГруппаШапкаСтажера`, `ТаблицаЗадачАП`, `КнопкаОтправитьНаСогласование`.

Допустимые значения `data-1c`:

| Значение | Элемент 1С | Типичное применение в прототипе |
|---|---|---|
| `ГруппаГоризонтальная` | Обычная группа, горизонтальная | Строка элементов |
| `ГруппаВертикальная` | Обычная группа, вертикальная | Колонка, панель, блок |
| `Страницы` / `Страница` | Группа «Страницы» | Вкладки верхнего уровня и вкладки стажёра |
| `КоманднаяПанель` | Командная панель | Панели кнопок над таблицами и под шапкой |
| `Кнопка` | Кнопка | Любая кнопка |
| `Подменю` | Подменю командной панели | Кнопка «⋮», «Добавить ▾» |
| `КонтекстноеМеню` | Контекстное меню таблицы | Меню строки таблицы |
| `ТаблицаФормы` | Таблица формы / динамический список | Все таблицы и дерево подразделений |
| `ДеревоФормы` | Таблица формы с данными ДеревоЗначений | Дерево подразделений |
| `Надпись` | Декорация-надпись | Тексты, заголовки, счётчики |
| `Гиперссылка` | Декорация-надпись с гиперссылкой | Кликабельный текст |
| `Картинка` | Декорация-картинка | Иконки, аватар |
| `ПолеВвода` | Поле ввода | Поиск, поля диалогов |
| `Флажок` | Поле флажка | Чекбоксы |
| `Тумблер` | Поле переключателя, вид «Тумблер» | Сегментные переключатели |
| `Индикатор` | Поле индикатора | Полосы прогресса с одним значением |
| `ОтдельнаяФорма` | Отдельная форма, открытая модально | Все диалоги |
| `ОповещениеПользователя` | `ПоказатьОповещениеПользователя()` | Всплывающие сообщения о результате действия |
| `НЕ_ПЕРЕНОСИТЬ` | — | Демо-переключатели и отладка, в 1С не переносятся |

### 3.3. Риски

Если элемент нельзя уверенно сделать штатными средствами, добавь атрибут `data-1c-risk`:

- `check` — вероятно реализуемо, нужно проверить на платформе (например, скругления у бейджей статусов в ячейках таблицы);
- `high` — потребует нестандартного решения (поле HTML-документа, диаграмма, программная генерация элементов).

Каждый такой элемент попадает в `1c-mapping.md` с пояснением и предлагаемым 1С-вариантом.

Заранее известные элементы с риском:

| Элемент | Риск | Вариант для 1С |
|---|---|---|
| Бейджи статусов в ячейках таблицы | `check` | Условное оформление: цвет фона и текста ячейки |
| Составная полоса прогресса (несколько цветов) | `high` | Диаграмма «Линейчатая с накоплением» либо набор декораций с программно вычисляемой шириной |
| Степпер этапов | `check` | Горизонтальная группа декораций-надписей с условной видимостью/цветом |
| Групповые строки «Корпоративный блок / Специальный блок» в таблице | `check` | Группировка динамического списка или дерево значений |
| Аватары-инициалы в кружке | `check` | Декорация-картинка из коллекции или без скругления |

## 4. Визуальный стиль

Опирайся на существующий макет 1С (светлая тема, синий основной цвет, жёлтое подчёркивание активной вкладки). Никакого «дизайнерского» переосмысления: задача — улучшить UX, а не сменить стиль.

### 4.1. Токены (`:root` в styles.css)

```css
--c-text: #1F2328;
--c-text-secondary: #6B7280;
--c-border: #E0E3E8;
--c-bg: #FFFFFF;
--c-bg-panel: #F7F8FA;
--c-bg-selected: #E8F0FE;
--c-primary: #1E6FE8;
--c-tab-active: #F5C400;
--c-success: #2E9E44;   --c-success-bg: #E6F4EA;
--c-warning: #D98A00;   --c-warning-bg: #FFF4DB;
--c-danger:  #D93025;   --c-danger-bg:  #FCE8E6;
--c-info:    #1E6FE8;   --c-info-bg:    #E8F0FE;
--c-neutral-bg: #EEF0F3;

--font: Arial, "Helvetica Neue", sans-serif;
--fs-s: 12px; --fs-m: 13px; --fs-l: 15px; --fs-xl: 18px;
--sp-1: 4px; --sp-2: 8px; --sp-3: 12px; --sp-4: 16px; --sp-5: 24px;
--radius: 4px;
```

Использовать только эти токены. Новые цвета и размеры не вводить.

### 4.2. Правила

- Базовый шрифт 13px. Заголовки блоков 15px, полужирные. Имя стажёра 18px.
- Кнопки: основная (заливка `--c-primary`), обычная (белая с рамкой), опасная (текст `--c-danger`, только в подменю). На одном экране не больше одной основной кнопки.
- Иконки — встроенные SVG 16×16, одноцветные, `currentColor`. Любая иконка без подписи обязана иметь `title`.
- Статусы — бейджи с фоном `*-bg` и текстом основного цвета.
- Тексты кнопок называют действие: «Отправить на согласование», а не «Отправить» или «ОК». Одно действие называется одинаково везде: в кнопке, в плашке, в сообщении об успехе.
- Пустые состояния всегда предлагают действие.
- Все подписи — по-русски, с правильным склонением числительных («1 стажёр», «2 стажёра», «5 стажёров»). Сделай общую функцию `plural(n, ['стажёр','стажёра','стажёров'])`.

## 5. Модель данных (`data.js`)

Имена ключей английские, в комментариях — предполагаемый объект 1С. Модель предварительная, её цель — обеспечить прототип данными.

### 5.1. Константы

```js
TODAY: '2026-07-25'          // «сегодня» для всех расчётов
CURRENT_USER_ID: 'u-petrova' // текущий пользователь — руководитель
REAPPROVAL_ON_CHANGE: true   // изменение согласованной АП требует повторного согласования (открытый вопрос, см. раздел 11)
LAG_THRESHOLD: 10            // отставание задач от времени, п.п., после которого показывается предупреждение
CLOSE_AVAILABLE_DAYS: 14     // за сколько дней до окончания доступно «Начать закрытие»
```

### 5.2. Сущности

```js
departments   // Справочник.Подразделения: id, name, parentId
users         // Справочник.Пользователи / ФизическиеЛица: id, fullName, shortName, role
trainees      // Стажёр (Справочник.Сотрудники + РегистрСведений статусов):
              //   id, fullName, position, departmentId, mentorId, headId,
              //   startDate, endDate, stage, changedAfterApproval (bool),
              //   rejectionComment (string|null), draftSince (date|null)
programs      // Документ.АдаптационнаяПрограмма: id, traineeId, templateId,
              //   defaultReviewerId, defaultObserverIds[], history[]
tasks         // ТЧ Задачи: id, programId, block ('corp'|'spec'), name, description,
              //   status ('not_started'|'in_progress'|'done'), deadline,
              //   reviewerId (null = по умолчанию), observerIds[] (пусто = по умолчанию),
              //   result (string|null), externalUrl (ссылка Forus Team, заглушка)
checklist     // ТЧ ЧекЛистПодготовки: id, traineeId, name, responsibleRole, responsibleId,
              //   offsetDays (отрицательное число — дни до выхода), done (bool),
              //   doneBy, doneAt, linkedDocType (null|'request0911'|'bitrix'|'program'),
              //   linkedDocNumber (null|string)
templates     // Справочник.ШаблоныАП: id, name, position (для рекомендации), tasks[]
notifications // генерируются функцией из состояния данных (см. 7.1), не хранятся
```

### 5.3. Производные значения (считать в app.js, не хранить)

- `overdue(task)` = `status !== 'done' && deadline < TODAY`. Просрочка — признак, а не статус. В бейдже просроченной задачи показывать «Просрочена», а не исходный статус.
- `timePct` = доля прошедших дней стажировки на `TODAY`, 0–100.
- `taskPct` = выполненные / все задачи АП.
- `lag` = `timePct - taskPct > LAG_THRESHOLD`.
- `daysToStart`, `daysToEnd`.
- Дата пункта чек-листа = `startDate + offsetDays`.

### 5.4. Этапы стажировки (`stage`)

| Код | Название в степпере | Главное действие | Вкладка по умолчанию |
|---|---|---|---|
| `found` | Подготовка к выходу | Создать АП | Подготовка к выходу |
| `draft` | Черновик АП | Отправить на согласование | Адаптационная программа |
| `approval` | Согласование | — (кнопка «Отозвать с согласования» обычная) | Адаптационная программа |
| `active` | Стажировка | «Начать закрытие стажировки» — неактивна, пока до окончания больше `CLOSE_AVAILABLE_DAYS` дней; рядом текст с причиной | Адаптационная программа |
| `closing` | Закрытие | Начать закрытие стажировки | Адаптационная программа |
| `closed` | Закрыта | — (всё только для просмотра) | Адаптационная программа |

Для прототипа добавь кнопку-переключатель в правом нижнем углу окна «Демо: этап ▾» (помечена `data-1c="НЕ_ПЕРЕНОСИТЬ"`), которая меняет этап выбранного стажёра. Она нужна для демонстрации состояний.

## 7. Компоненты и поведение

### 7.1. Уведомления

Уведомления вычисляются функцией `getNotifications(trainee)` из текущего состояния данных и показываются в трёх местах:

1. **Плашки** в карточке стажёра — полный текст и кнопка действия.
2. **Маркеры** в дереве и списке — короткий текст справа от ФИО.
3. **Счётчик** на верхней вкладке.

| Условие | Тип | Текст плашки | Кнопка в плашке | Маркер |
|---|---|---|---|---|
| `found`, АП нет | warning | Для стажёра нужно создать адаптационную программу. Выход через N дней | Создать АП | Нет АП |
| Есть просроченные пункты чек-листа | danger | Просрочено пунктов подготовки к выходу: N | Показать | N просроч. |
| `draft`, черновик ≥ 2 дней | warning | Адаптационная программа не отправлена на согласование уже N дней | Отправить на согласование | Черновик |
| `draft` и есть `rejectionComment` | danger | АП возвращена на доработку: «комментарий» | Отправить на согласование | Возврат |
| `approval` | info | АП на согласовании с ДД.ММ.ГГ | — | На согл. |
| `changedAfterApproval` | warning | АП изменена после согласования. Отправьте её на повторное согласование | Отправить на согласование | Изменена |
| `active`, есть просроченные задачи | danger | Просрочено задач: N | Показать | N просроч. |
| `active`, `lag` | warning | Задачи отстают от графика: выполнено X% при прошедших Y% срока | Показать невыполненные | — |
| До окончания ≤ `CLOSE_AVAILABLE_DAYS` | info | До окончания стажировки N дней | Начать закрытие стажировки | Закрытие через N дн. |

Правила:

- Плашки сортируются: danger → warning → info. Видно не больше трёх, остальные — под ссылкой «Ещё N уведомлений».
- Закрыть (×) можно только info-плашку. Закрытие действует до перезагрузки.
- В маркере дерева показывается один маркер — самый важный.
- «Показать» переключает на нужную вкладку и включает соответствующий фильтр таблицы.
- В 1С плашка — горизонтальная группа с цветом фона и управляемой видимостью: `data-1c="ГруппаГоризонтальная"`.

### 7.2. Левая панель

**Счётчики** — 4 карточки в две строки по две:

| Карточка | Этапы | Иконка/цвет |
|---|---|---|
| Ожидают АП | `found`, `draft` | warning |
| На согласовании | `approval` | info |
| Идёт стажировка | `active` | success |
| Ожидают закрытия | `closing` | warning |

- Число крупно, подпись со склонением.
- Клик по карточке фильтрует дерево, список и сводную таблицу по этим этапам. Активная карточка — рамка `--c-primary` и фон `--c-bg-selected`. Повторный клик сбрасывает фильтр.
- При активном фильтре под карточками строка «Фильтр: Ожидают АП ✕».

**Поиск** — поле «Поиск по ФИО или подразделению». Ищет по подстроке без учёта регистра. У найденных стажёров и подразделений сохраняются родительские узлы, ветки раскрываются. Если ничего не найдено: «Никого не нашли» и ссылка «Сбросить поиск».

**Флажок** «Скрыть подразделения без стажёров», по умолчанию включён. Кнопка-воронка из текущего макета удаляется.

**Тумблер режима:** «Структура | Требуют внимания».

**Режим «Структура»** — дерево:

- Подразделение: стрелка раскрытия, название, число стажёров в поддереве с учётом фильтров, «(N)».
- Стажёр: цветная точка этапа, ФИО, справа маркер (7.1). Цвет точки: warning — `found`, `draft`, `closing`; info — `approval`; success — `active`; нейтральный — `closed`. Цвет маркера просрочек — danger.
- Выбранный стажёр подсвечен фоном `--c-bg-selected`. При выборе стажёра из любого места (сводная таблица, список) дерево раскрывается до него.
- Отступ уровня 16px. Стажёры визуально отличаются от подразделений: обычное начертание против полужирного у подразделений.

**Режим «Требуют внимания»** — плоский список стажёров, у которых есть уведомления warning или danger. Сортировка: сначала danger, затем по ближайшему сроку. Строка: ФИО, под ним подразделение (серым), справа маркер. Пустой список: «Действий не требуется».

**Свернуть** — панель сворачивается в полосу 40px с кнопкой «Развернуть» (иконка, `title`).

Все изменения этапа мгновенно отражаются в степпере, плашках, дереве, счётчиках и сводной таблице.

### 7.5. Вкладка «Адаптационная программа»

#### 7.5.1. Блок прогресса

Горизонтальная группа из двух частей.

**Слева:**

- Составная полоса на всю ширину: выполнено (success) → в работе (primary) → просрочено (danger) → не начато (нейтральный). `data-1c-risk="high"`.
- Под ней счётчики-гиперссылки: «Выполнено 14 (58%)», «В работе 7 (29%)», «Просрочено 3 (13%)», «Не начато N». Нулевые не показывать. Просроченная задача считается только в «Просрочено».
- Клик по счётчику фильтрует таблицу. Над таблицей появляется «Показаны: Просрочено ✕». Повторный клик или ✕ снимает фильтр.

**Справа** — прогресс по блокам:

- «Корпоративный блок: 10 из 14» + индикатор;
- «Специальный блок: 4 из 10» + индикатор.

#### 7.5.2. Командная панель таблицы

```
[Все (24) | Корпоративный (14) | Специальный (10)]  [Добавить ▾]  |  Выбрано: 3  [Назначить проверяющего] [Наблюдатели] [Перенести срок] [Удалить]
```

- Тумблер блоков с количеством задач.
- «Добавить ▾» → «Новая задача» (диалог карточки задачи) и «Из шаблона…» (диалог выбора задач из шаблонов с флажками).
- Кнопки массовых действий неактивны, пока ничего не выбрано. «Выбрано: N» видно только при N > 0.

#### 7.5.3. Таблица задач

| Колонка | Содержимое |
|---|---|
| ☐ | Флажок выбора строки. В заголовке — выбрать все видимые. **Это только выбор, не отметка выполнения.** |
| Задача | Наименование; под ним серым первые ~80 символов описания |
| Статус | Бейдж: Не начата (нейтр.), В работе (info), Выполнена (success), Просрочена (danger) |
| Срок | Дата; у просроченной — danger-цветом и «(−3 дн.)» |
| Проверяющий | Краткое ФИО. Если унаследовано от АП — серым с пометкой «по умолч.» |
| Наблюдатели | До двух кратких ФИО и «+N». Если унаследованы — «по умолч.» |

- Сортировка кликом по «Статус» и «Срок»; по умолчанию — порядок задач в АП.
- Пустой результат фильтра: «Нет задач с таким статусом» и ссылка «Сбросить фильтр».

#### 7.5.4. Правила редактирования АП

| Этап | Редактирование |
|---|---|
| `draft` | Свободно |
| `approval` | Запрещено. Над таблицей надпись «АП на согласовании. Чтобы изменить задачи, отзовите её с согласования». Кнопки изменения неактивны, флажки выбора скрыты |
| `active`, `closing` | Разрешено. Каждое изменение сразу применяется и пишется в историю. При `REAPPROVAL_ON_CHANGE = true` первое изменение ставит `changedAfterApproval = true`, и появляется плашка из 7.1 |
| `closed` | Только просмотр |

«Изменение» = добавление, удаление, изменение наименования, срока, блока, проверяющего, наблюдателей, порядка. Смена статуса и результата не считается изменением АП.

Удаление всегда через подтверждение «Удалить задач: N?».

#### 7.5.5. Пустое состояние (АП нет)

- Заголовок «Адаптационная программа ещё не создана».
- Текст «Выход стажёра 29.07.26. Программу нужно создать и согласовать до выхода.»
- Три варианта в строку, у каждого — короткое пояснение и кнопка:
  1. **По шаблону** — «Задачи и сроки подставятся из шаблона должности». Если есть шаблон для должности стажёра — пометка «Подходит для должности „Аналитик“». Кнопка «Выбрать шаблон».
  2. **Скопировать у другого стажёра** — «Возьмите АП коллеги на похожей должности». Кнопка «Выбрать стажёра».
  3. **С нуля** — «Пустая программа, задачи добавите сами». Кнопка «Создать пустую АП».

Результат любого варианта:

- создаётся АП, этап → `draft`, `draftSince = TODAY`;
- сроки задач из шаблона считаются от `startDate` (у задач шаблона хранится смещение в днях);
- пункт чек-листа «Создать АП» отмечается выполненным;
- оповещение «АП создана».

Пустая АП показывает в таблице: «В программе пока нет задач» и ссылки «Добавить задачу» и «Добавить из шаблона».

### 7.6. Вкладка «Подготовка к выходу»

**Сводка над таблицей:**

- до выхода: «До выхода: 4 дня» и «Готово: 2 из 7» с индикатором;
- после выхода: «Стажёр вышел 20.05.26» и «Готово: 7 из 7».

**Командная панель:** «Добавить пункт», «↑», «↓», «Заполнить по шаблону» (с подтверждением «Текущий список будет заменён»), тумблер «Все | Мои» (Мои — пункты, где `responsibleId === CURRENT_USER_ID`).

**Таблица:**

| Колонка | Содержимое |
|---|---|
| ☐ | Флажок «выполнено». Здесь флажок — это отметка выполнения |
| Пункт | Наименование |
| Ответственный | Роль; под ней серым краткое ФИО |
| Срок | Дата; под ней серым «за 5 дн. до выхода» |
| Статус | Не выполнено (нейтр.) / Просрочено (danger) / Выполнено (success). У выполненного под бейджем серым «Петрова А. Е., 24.07» |
| Действие | Гиперссылка по `linkedDocType` (см. ниже) |

Действия:

### 7.9. Режим разметки 1С (только для прототипа)

Сочетание Shift+D включает/выключает режим, в котором:

- у каждого элемента с `data-1c` пунктирная рамка;
- в левом верхнем углу элемента мелкая подпись `data-1c` + `data-1c-name`;
- элементы с `data-1c-risk="check"` — оранжевая рамка, с `high` — красная.

В консоли доступна функция `check1c()`: возвращает список элементов `button, input, select, table, [data-tab]`, у которых нет `data-1c` или `data-1c-name`.

Весь код режима помечен `data-1c="НЕ_ПЕРЕНОСИТЬ"` / комментарием `// НЕ_ПЕРЕНОСИТЬ`.

## 8. Сквозные требования

- Одно состояние — один источник. Весь рендер идёт из `window.DATA` и объекта `state` (выбранный стажёр, активная вкладка, фильтры, выбранные строки). После любого изменения данных вызывается общий `render()` затронутых зон. Никакого «ручного» изменения DOM в обход данных.
- Все даты в интерфейсе — формат `ДД.ММ.ГГ`, в истории — `ДД.ММ.ГГ ЧЧ:ММ`.
- Неактивная кнопка всегда объясняет причину: текстом рядом (для главного действия) или через `title` (для второстепенных).
- Фокус клавиатуры виден (outline 2px `--c-primary`).
- Текст не обрезается без многоточия и `title` с полным значением.
- При ширине 1366px нет горизонтальной прокрутки страницы. Широкие таблицы прокручиваются внутри своего контейнера.

## 12. Открытые вопросы

Не блокируют прототип. Для каждого в прототипе принято временное решение — оно указано в скобках. Не расширяй решение сверх указанного.

1. Требует ли изменение согласованной АП повторного согласования? *(Да, флаг `REAPPROVAL_ON_CHANGE`.)*
2. Нужен ли у задачи статус «На проверке», раз есть проверяющие? *(Нет.)*
3. «Начать закрытие стажировки» запускает отдельный маршрут согласования? *(Нет, сразу этап «Закрыта».)*
4. Когда доступно закрытие: за N дней до окончания или после выполнения всех задач? *(За 14 дней.)*
5. Можно ли менять АП, пока она на согласовании? *(Нет, только после отзыва.)*
6. Что делали три кнопки без подписей в текущем макете? *(Заменены на «Проверяющие и наблюдатели» и «История изменений АП».)*
7. Откуда приходит результат задачи и её статус — из Forus Team? Как часто синхронизируется? *(Статус и результат — просто данные в `data.js`, ссылка — заглушка.)*
8. Кто может отменить стажировку — только руководитель стажировки или любой руководитель выше по структуре? *(Любой, кто видит стажёра.)*
